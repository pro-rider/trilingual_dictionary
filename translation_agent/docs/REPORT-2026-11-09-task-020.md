## P0-1 Production-database guard — VERIFIED

Defect: a path-only guard (`realpath` + filename + path fragment). Three
variants walked past it: `?mode=rw`, trailing whitespace, hard link.

Change (`src/translation_agent/config.py`): four independent controls —
ambiguity refusal (`file:`, `://`, `?`, `#`, control characters, leading/
trailing whitespace), name + marker rules, **inode and content identity against
a protected manifest**, and fail-closed on unreadable manifests or unstattable
targets. The manifest is produced by the new `scripts/protect_manifest.py`
(`{path, dev, ino, bytes, sha256}`).

Evidence: `tests/security/test_guard_bypass.py` — 20 tests. Refused: absolute,
relative, `.`/`..`, symlink, mixed separators, uppercase name, same name in an
unrelated directory, env override, `file:` URI, `?mode=rw`, trailing space,
**hard link** (by dev/ino), **byte-identical copy** (by sha256), manifest-listed
path, unreadable manifest, missing explicit manifest. Allowed: unrelated temp
database. The three former xfail tests are now ordinary passing tests.

Limit, stated rather than hidden: hard-link protection is only active when the
manifest is present. `guard` prints `hardlink_protection: false` without one,
and `docs/SECURITY-CONTRACT.md` records that a manifest captured before the file
was replaced is stale. Inode comparison is meaningless on filesystems reporting
`st_ino = 0`.

## P0-2 Request fingerprint v2 — VERIFIED

Defect: v1 hashed the configuration (sense key, provider, model, prompt), not
the input, so a corrected gloss kept the same fingerprint and a stale candidate
was silently reused.

Change (`domain/identity.py`): v1 frozen verbatim as `request_fingerprint_v1`
(also still exported under its old name); new `request_fingerprint_v2` hashes
word, pinyin, gloss, `source_revision_hash`, language, provider, model, model
parameters, prompt version + checksum, rendered prompt hash, output schema
version and `variant_key`. Both values are stored; nothing stored previously is
recomputed. New `docs/FINGERPRINT-CONTRACT.md`.

Evidence: `tests/test_fingerprint_v2.py` (9) — stable for identical input;
changes on gloss correction, word, pinyin, rendered prompt, parameters, variant;
v1 remains constant and distinct; golden literal values recorded.
End-to-end: `tests/test_multi_generation.py::test_corrected_gloss_triggers_a_new_request`
— 2 requests stored, the newer one carrying `source_gloss = "body of water"`.

## P0-3 Schema verification — VERIFIED

Defect: table names plus one metadata row. A ledger with a missing UNIQUE
constraint or a wrong column type passed.

Change: DDL moved to `ledger/schema.py` (single source of truth); new
`ledger/schema_verifier.py` builds the expected schema in memory and compares
columns (name/type/nullability/PK), indexes (uniqueness, columns, partiality,
names), foreign keys and normalised DDL; reports every difference at once; never
migrates or repairs.

Evidence: `tests/test_schema_verifier.py` (9) — healthy ledger verifies with a
`schema_fingerprint`; extra column, dropped index, dropped table, wrong column
type, missing unique index, legacy schema_version all fail closed; verification
leaves the tampered file unchanged.

Contract change: schema version `1 → 2`. **A v1 ledger will not open** — it is
refused with `LedgerSchemaMismatch`. That is deliberate (no silent migration); a
v1 file must be replaced, not upgraded.

## P0-4 Non-destructive rollback — VERIFIED (contract change)

Defect: `rollback_batch` deleted candidate and request rows, leaving audit
events pointing at rows that no longer existed, and allowing a later retry to
recreate the same text with no trace.

Change: rollback writes one `rolled_back` event per candidate (idempotent),
sets `candidates.state` and `generation_requests.state` to `rolled_back`, and
keeps payload, provenance, request link and history. New
`generation_requests.state` column.

Evidence: `tests/test_atomicity.py::test_rollback_batch_retires_rows_and_keeps_all_evidence`
— 3 candidates still present, all `rolled_back`, payload and request id intact,
events `needs_review ×3` and `rolled_back ×3`.
Disclosure: the previous test asserted deletion (`count_candidates == 0`). It was
rewritten because the contract changed on purpose; no other test was removed.

## P1-5 Multi-generation identity — VERIFIED

Candidate uniqueness is now
`(candidate_hash, sense_key, target_language, COALESCE(variant_key,'base'))`
(unique expression index `idx_candidates_identity`). A variant is its own row;
identical text within the same variant is deduplicated by content lookup, not by
candidate id, and is reported as `skipped_existing`.

Evidence: `tests/test_multi_generation.py` (4) — variant creates a second
request and candidate; same-variant duplicate is skipped (1 candidate, 1
request); variant may repeat base text (2 candidates, 2 requests); rejected
candidate stays inspectable and can return to review.

## P1-6 Concurrency — VERIFIED

`timeout=0.0` retained; the transaction helper retries `SQLITE_BUSY`/`LOCKED`
with configurable bounded exponential backoff (`busy_retries`, default 5;
`busy_backoff_ms`, default 20) and raises `LedgerBusy` when exhausted. Non-lock
errors are not retried. Provider calls are never re-issued because persistence
failed.

Evidence: `tests/test_concurrency.py` (4) — a competing writer holding
`BEGIN IMMEDIATE` for 0.15 s: the ledger waits and succeeds; a 2 s hold with
`busy_retries=2` produces `LedgerBusy`; a SQL error raises immediately; a failed
transaction leaves no row.

## P1-7 Raw-response retention — VERIFIED

`retention_days` was stored metadata with no enforcement. New
`audit/retention.py` provides `plan_retention` / `apply_retention` and the CLI
command `retention` (plan by default, `--apply` to erase). Payload becomes
`[PURGED]`, bytes 0, `purged_at` set; the row, request link, candidate and
events survive; a `last_retention_run` marker is written. Generation never calls
it.

Evidence: `tests/test_retention.py` (6) — nothing expires immediately; plan is
read-only; apply erases only payload; idempotent second run purges 0; candidate
text unchanged; a 365-day window keeps the payload.
Limit: only regex redaction plus size cap; `docs` says so and no stronger claim
is made.
